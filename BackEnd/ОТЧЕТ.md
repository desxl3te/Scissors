# Отчёт о тестировании бэкенда «Scissors Bar»

## Общая информация

Проект: Бэкенд для системы бронирования "Scissors Bar"  
Фреймворки: FastAPI (основной API), Flask (дашборд)  
База данных: MySQL  
Тестовый фреймворк: pytest 9.0.3  
Дополнительные плагины: pytest-cov, pytest-mock, anyio  
Версия Python: 3.13.2  
Результат: 48 тестов пройдено, покрытие 83%

## Структура тестов

- test/conftest.py — Глобальные фикстуры и моки
- test/test_config.py — Тесты хелпер-функций конфигурации
- test/test_main.py — Тесты основного приложения FastAPI
- test/test_dashboard.py — Тесты Flask-дашборда
- test/test_dependencies.py — Тесты зависимостей (авторизация, сериализация)
- test/test_api/test_auth.py — Тесты авторизации (регистрация, вход, профиль)
- test/test_api/test_events.py — Тесты эндпоинтов событий
- test/test_api/test_public.py — Тесты публичных эндпоинтов
- test/test_api/test_reservations.py — Тесты бронирования столиков
- test/test_api/test_support.py — Тесты поддержки
- test/test_api/test_users.py — Тесты пользователей
- test/test_db/test_bootstrap.py — Тесты инициализации БД
- test/test_db/test_repository.py — Тесты репозитория (работа с БД)

## Как запускать тесты

### Базовый запуск

Перейти в папку backend:
cd backend

Активировать виртуальное окружение (если нужно):
.\.venv-1\Scripts\Activate.ps1

Запустить все тесты:
pytest test/ -v --no-cov

### С покрытием кода

Запуск с генерацией отчёта покрытия:
pytest test/ --cov=app --cov=dashboard_service --cov-report=html --cov-report=term

Открыть HTML-отчёт в браузере:
Start-Process htmlcov/index.html

### Запуск конкретного файла или теста

Только тесты авторизации:
pytest test/test_api/test_auth.py -v

Только один конкретный тест:
pytest test/test_api/test_auth.py::TestAuth::test_login_success -v

Тесты с отладочным выводом (показ print()):
pytest test/test_api/test_auth.py -v -s

### Полезные флаги pytest

- -v — подробный вывод (verbose)
- -s — показать вывод print() в тестах
- -x — остановиться после первой ошибки
- --tb=short — краткий стектрейс при ошибках
- --no-cov — отключить покрытие (для скорости)
- --cov=app — считать покрытие для модуля app
- --cov-report=html — сгенерировать HTML-отчёт

## Настройка pytest.ini

Файл pytest.ini в корне backend/ содержит конфигурацию pytest:

[pytest]

# Пути к папкам с тестами
testpaths = test

# Имена файлов с тестами
python_files = test_*.py

# Имена классов с тестами
python_classes = Test*

# Имена функций с тестами
python_functions = test_*

# Дополнительные опции по умолчанию
addopts =
    -v
    --strict-markers
    --no-cov
    --tb=short

# Настройки asyncio для асинхронных тестов
asyncio_mode = auto

### Зачем нужен pytest.ini?

- Единая конфигурация для всей команды
- Не нужно помнить флаги при каждом запуске
- Строгая проверка маркеров предотвращает опечатки в @pytest.mark.*
- Автоматический поиск тестов по указанным паттернам

## Фикстуры и моки

### conftest.py — глобальные фикстуры

**setup_test_env (область: session)**  
Устанавливает тестовые переменные окружения. Восстанавливает оригинальные значения после тестов.

**reset_all_mocks (область: function, autouse)**  
Создаёт чистые моки БД и безопасности для каждого теста. Патчит mysql.connector.connect, passlib и jose на низком уровне.

**fastapi_client (область: function)**  
Создаёт TestClient для FastAPI с применёнными моками. Очищает кеш импортов для корректной работы моков.

**flask_client (область: function)**  
Создаёт тестовый клиент для Flask-дашборда. Мокирует чтение конфигурационных файлов.

**mock_db_cursor (область: function)**  
Удобный доступ к мок-курсорам БД в тестах.

**full_user_data (область: function)**  
Возвращает полные данные пользователя для моков. Содержит все поля, требуемые функцией serialize_user.

### Как работают моки

- База данных: mysql.connector.connect заменяется на MagicMock, все запросы возвращают тестовые данные
- Безопасность: passlib.context.CryptContext.verify всегда возвращает True (или настраивается в тесте), jose.jwt.decode возвращает {"sub": "1", "email": "t@t.com"}
- Файлы: app.core.files.read_json возвращает тестовый JSON

### Почему моки на уровне библиотек?

При импорте from module import func Python создаёт локальную ссылку на функцию. Патч module.func не обновляет эту ссылку. Патч на уровне библиотеки (passlib, jose) перехватывает вызов гарантированно, независимо от способа импорта.
